### Что такое база данных — за одну минуту

- **База данных (БД)** — набор таблиц, в которых хранятся данные. Похоже на книгу Excel с несколькими листами.
- **СУБД** — программа, которая хранит базы данных и отвечает на запросы. Мы будем работать с **PostgreSQL** (произносится «постгрес») — одной из самых популярных СУБД в мире.
- **Таблица** — один «лист». У нас есть таблицы `products` (товары), `clients` (клиенты), `orders` (заказы) и другие.
- **Строка** — одна запись: один товар, один клиент, один заказ.
- **Столбец** — одно свойство: название, цена, город.
- **SQL** — язык, на котором у базы *спрашивают*: «покажи товары дороже 1000 рублей», «сколько у нас клиентов в Казани?». Такой вопрос называется **запросом**.

## Шаг 3. Осмотрись

В дереве слева раскрой **shop** → **Schemas** → **public** → **Tables** (если таблиц не видно — нажми на **Tables** правой кнопкой → **Refresh**). Чтобы посмотреть содержимое таблицы, нажми на неё правой кнопкой → **View/Edit Data** → **All Rows**.

Пролистай каждую таблицу. Вот как они связаны:

```
 categories              products                    order_items                 orders               clients
┌────────────┐        ┌───────────────┐          ┌───────────────┐        ┌──────────────┐      ┌───────────┐
│ id         │◄───────┤ category_id   │          │ id            │        │ id           │      │ id        │
│ name       │        │ id            │◄─────────┤ product_id    │        │ client_id    ├─────►│ name      │
└────────────┘        │ name          │          │ order_id      ├───────►│ order_date   │      │ city      │
                      │ price         │          │ quantity      │        │ status       │      └───────────┘
                      │ stock         │          │ price         │        └──────────────┘
                      └───────────────┘          └───────────────┘
```

> 💡 pgAdmin умеет рисовать такую схему сам: правой кнопкой на **shop** → **ERD For Database**.

| Таблица | Что хранит | Важные столбцы |
|---|---|---|
| `categories` | категории товаров | `name` — название категории |
| `products` | товары | `price` — цена в рублях, `stock` — сколько штук на складе, `category_id` — номер категории |
| `clients` | клиенты-компании | `name` — название, `city` — город |
| `orders` | заказы | `client_id` — кто заказал, `order_date` — дата, `status` — Новый / Оплачен / Доставлен / Отменён |
| `order_items` | строки заказов: что и сколько купили | `order_id`, `product_id`, `quantity` — количество, `price` — цена за штуку |

Два важных слова:

- **Первичный ключ** (`id`) — уникальный номер строки. У двух товаров не может быть одинакового `id`.
- **Внешний ключ** (`category_id`, `client_id`, `order_id`, `product_id`) — ссылка на `id` в другой таблице. Например, `category_id = 3` у товара означает «этот товар из категории с `id = 3`», то есть из «Канцелярии». Стрелки на схеме — это и есть такие ссылки.

## Шаг 4. Как писать и запускать запросы

Открой `queries.sql` в Блокноте — так же, как журнал команд в дне 1:

```bash
notepad queries.sql &
```

Внутри — список заданий. Под каждой строкой `-- Задание N` пиши свой запрос. Строки, которые начинаются с `--`, — это **комментарии**: база их не читает, они для людей.

Порядок работы над каждым заданием:

1. В pgAdmin открой **Query Tool** для базы `shop` (как в шаге 2) и напиши запрос там. Если в окне уже есть старый текст — сотри его.
2. Запусти запрос: **F5** (или кнопка ▶). Если выделить часть текста мышкой, выполнится только выделенное.
3. Результат появится внизу, на вкладке **Data Output**, а ошибки — на вкладке **Messages**. Сверь результат с подсказкой «Проверь себя» в задании.
4. Если всё сошлось — скопируй запрос в `queries.sql` под нужное задание и сохрани файл (**Ctrl + S**).

Получится примерно так:

```sql
-- Задание 1. Все товары (все столбцы)
SELECT * FROM products;
```

**Правила SQL, которые сэкономят тебе нервы:**

- Каждый запрос заканчивается точкой с запятой `;`.
- Текст и даты пишутся в **одинарных** кавычках: `'Казань'`, `'2025-01-15'`. Числа — без кавычек: `1000`. Двойные кавычки `"…"` в PostgreSQL означают имя столбца, а не текст — не путай!
- Большие и маленькие буквы в **тексте** различаются: `'Казань'` и `'казань'` — разные строки. А в командах — нет: `SELECT` и `select` работают одинаково. Команды принято писать большими буквами, чтобы их было легко отличить.
- Порядок частей запроса строгий: `SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT …`

## Часть B. Подсчёты и группировка

### Шпаргалка

**Агрегатные функции** сворачивают много строк в одно число:

| Функция | Что считает |
|---|---|
| `COUNT(*)` | количество строк |
| `SUM(столбец)` | сумму |
| `AVG(столбец)` | среднее |
| `MIN(столбец)`, `MAX(столбец)` | наименьшее и наибольшее |
| `ROUND(число)` | округляет до целого |

```sql
SELECT COUNT(*) FROM orders;                         -- сколько всего заказов
SELECT MAX(price) FROM products;                     -- самая высокая цена
SELECT SUM(quantity) FROM order_items;               -- сколько штук продано всего
SELECT SUM(quantity * price) FROM order_items;       -- считать можно и выражения
```

**`GROUP BY`** делит строки на группы и считает отдельно для каждой группы:

```sql
SELECT status, COUNT(*) FROM orders GROUP BY status;
```

Строки могут идти в любом порядке — если порядок важен, добавь `ORDER BY`.

```
Доставлен | 11
Новый     | 4
Оплачен   | 3
Отменён   | 2
```

Столбцу с результатом можно дать имя через `AS`, а потом сортировать по нему:

```sql
SELECT status, COUNT(*) AS cnt FROM orders GROUP BY status ORDER BY cnt DESC;
```

Сортировать можно по нескольким столбцам сразу: `ORDER BY cnt DESC, status` — сначала по количеству, а при равенстве — по статусу.

**`HAVING`** — это `WHERE` для групп. `WHERE` отбирает строки *до* группировки, `HAVING` — группы *после*:

```sql
SELECT status, COUNT(*) FROM orders GROUP BY status HAVING COUNT(*) > 3;
```

## Часть C. Несколько таблиц

### Шпаргалка

В таблице `products` у товара есть только **номер** категории (`category_id`), а её название лежит в таблице `categories`. Чтобы увидеть их рядом, таблицы нужно **соединить** — `JOIN`:

```sql
SELECT order_items.order_id, products.name, order_items.quantity
FROM order_items
JOIN products ON products.id = order_items.product_id;
```

- `JOIN products` — «присоедини таблицу `products`»;
- `ON products.id = order_items.product_id` — **как** соединять: строка заказа ищет товар, у которого `id` равен её `product_id`. Это та самая стрелка со схемы в шаге 3;
- `products.name` — «столбец `name` из таблицы `products`». Писать имя таблицы нужно, когда в обеих таблицах есть столбец с одинаковым именем (например, `id` или `name`).

Чтобы не писать длинные имена, таблицам дают короткие **псевдонимы**:

```sql
SELECT i.order_id, p.name, i.quantity
FROM order_items i
JOIN products p ON p.id = i.product_id;
```

Соединять можно больше двух таблиц — просто добавь ещё один `JOIN … ON …`. А после соединения работают и `WHERE`, и `GROUP BY`, и `ORDER BY`.

**`LEFT JOIN`** оставляет **все** строки левой (первой) таблицы, даже если пары для них не нашлось. Там, где пары нет, в столбцах правой таблицы будет пусто — `NULL`. Так можно найти «одиночек»:

```sql
-- клиенты, у которых нет ни одного заказа
SELECT c.name
FROM clients c
LEFT JOIN orders o ON o.client_id = c.id
WHERE o.id IS NULL;
```

> ⚠️ Проверка на пустоту пишется `IS NULL`, а не `= NULL`.

## Часть D. Изменение данных

До сих пор ты только *читал* данные. Теперь будешь их менять.

### Шпаргалка

```sql
-- добавить строку; id можно не указывать — база придумает его сама
INSERT INTO clients (name, city) VALUES ('ООО «Новый клиент»', 'Самара');

-- изменить строки
UPDATE clients SET city = 'Казань' WHERE id = 12;

-- удалить строки
DELETE FROM clients WHERE id = 12;

-- создать таблицу
CREATE TABLE notes (
    id   INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    text TEXT NOT NULL
);
```

- `INTEGER` — целое число, `TEXT` — текст, `DATE` — дата.
- `PRIMARY KEY` — первичный ключ.
- `GENERATED ALWAYS AS IDENTITY` — номер ставится автоматически: 1, 2, 3… Тогда при `INSERT` столбец `id` указывать не нужно. Без этих слов PostgreSQL номер сам **не** поставит, и `INSERT` без `id` выдаст ошибку.
- `NOT NULL` — значение обязательно, пустым оставить нельзя.

> ⚠️ **`UPDATE` и `DELETE` без `WHERE` меняют ВСЮ таблицу.** `DELETE FROM products;` удалит все товары. Всегда сначала проверь условие обычным `SELECT … WHERE …` — и только потом меняй.
>
> Если что-то сломал — заново выполни `shop.sql` (шаг 2), и база станет как новенькая.

## Если что-то пошло не так

pgAdmin может показывать ошибки по-английски или по-русски — ниже оба варианта.

<details>
<summary><code>relation "products" does not exist</code> / <code>отношение "products" не существует</code></summary>

Запрос ушёл не в ту базу, или данные ещё не загружены. Посмотри на заголовок вкладки Query Tool: там должно быть `shop/postgres@…`. Если там `postgres/postgres@…` — закрой вкладку, нажми слева на базу **shop** и открой Query Tool заново. Если база правильная — выполни `shop.sql` (шаг 2).
</details>

<details>
<summary><code>column "Казань" does not exist</code> / <code>столбец "Казань" не существует</code></summary>

Текст написан в двойных кавычках. В PostgreSQL текст пишется только в одинарных: `WHERE city = 'Казань'`.
</details>

<details>
<summary><code>column "..." does not exist</code> / <code>столбец "..." не существует</code></summary>

Опечатка в имени столбца, или столбец взят не из той таблицы. Сверь имя со схемой в шаге 3.
</details>

<details>
<summary><code>syntax error at or near "..."</code> / <code>ошибка синтаксиса (примерное положение: "...")</code></summary>

PostgreSQL не понял запрос в месте, которое указано в кавычках. Чаще всего это:

- пропущена запятая между столбцами: `SELECT name price` → `SELECT name, price`;
- лишняя запятая перед `FROM`: `SELECT name, price, FROM` → `SELECT name, price FROM`;
- части запроса стоят не в том порядке (`ORDER BY` раньше `WHERE`).
</details>

<details>
<summary><code>column reference "id" is ambiguous</code> / <code>неоднозначная ссылка на столбец "id"</code></summary>

Столбец `id` есть в обеих соединённых таблицах, и база не знает, какой ты имеешь в виду. Укажи таблицу: `p.id` или `c.id`.
</details>

<details>
<summary><code>must appear in the GROUP BY clause</code> / <code>должен фигурировать в предложении GROUP BY</code></summary>

При группировке в `SELECT` можно писать только столбцы из `GROUP BY` и агрегатные функции (`COUNT`, `SUM`, …). Например, `SELECT city, name, COUNT(*) FROM clients GROUP BY city` не сработает: у одного города много названий клиентов, и база не знает, какое из них показать.
</details>

<details>
<summary><code>operator does not exist: date ~~ unknown</code> / <code>оператор не существует: date ~~ unknown</code></summary>

`LIKE` работает только с текстом, а `order_date` — это дата. Для дат используй сравнения и `BETWEEN`: `order_date BETWEEN '2025-01-01' AND '2025-12-31'`.
</details>

<details>
<summary><code>null value in column "id"</code> / <code>значение NULL в столбце "id"</code></summary>

В `CREATE TABLE` у столбца `id` нет `GENERATED ALWAYS AS IDENTITY`, поэтому база не ставит номер сама. Удали таблицу (`DROP TABLE employees;`), исправь `CREATE TABLE` и выполни его снова.
</details>

<details>
<summary>Запрос выполнился, но ничего не вернул</summary>

- В тексте различаются большие и маленькие буквы: `'казань'` ≠ `'Казань'`.
- Даты пишутся так: `'2025-01-15'` — год, месяц, день, через дефис, в кавычках.
- Проверь условие: может быть, перепутал `>` и `<`.
</details>

<details>
<summary><code>relation "employees" already exists</code> / <code>отношение "employees" уже существует</code>, или ручка добавилась два раза</summary>

Ты запустил запрос второй раз. Заново выполни `shop.sql` (шаг 2) — он сбросит базу. Потом выполни задания 20–23 по одному разу.
</details>

<details>
<summary><code>password authentication failed for user "postgres"</code> / <code>пользователь "postgres" не прошёл проверку подлинности</code></summary>

Неверный пароль. Это пароль, который ты придумал при установке PostgreSQL в шаге 1. Если на компьютере PostgreSQL ставили до тебя — спроси пароль у организаторов.
</details>
